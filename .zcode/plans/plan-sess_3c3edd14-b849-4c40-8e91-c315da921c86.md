# JazzCash Fix Plan — Security First, Then Guide Conformance (no Refund)

Approving this unlocks the edits; work starts immediately with the security fixes.

## Phase 1 — Security fixes (before anything else)

- **S1. Lock down `Donations` collection** (`src/collections/Donations.ts`) — currently `read/create/update: () => true`, so `GET /api/donations` publicly dumps donor names, mobiles, amounts, auth codes and raw IPN payloads, and anyone can forge/flip records. Change to authenticated-user-only access (admin panel keeps working; our routes use the Local API which bypasses access control); `delete` stays `false`.
- **S2. Stop logging credentials** (`src/lib/jazzcash/client.ts`) — redact `pp_Password`/`pp_SecureHash` (full payloads only in sandbox; production gets a one-line summary).
- **S3. Strip secrets from IPN persistence + logs** (`ipn/route.ts`) — IPN bodies carry `pp_Password` per the guide sample; store/log a redacted copy only.
- **S4. Harden initiate validation** — strict type/length checks (`donorName` currently crashes with a 500; unvalidated `amount` can reach the gateway as `"NaN"`); return generic 500 text, log details server-side.
- **S5. Rate-limit initiate + status** — in-memory per-IP fixed-window limiter (no new deps), 429 + Retry-After.
- **S6. Status route minimal fields** — drop `responseMessage`, keep txnRefNo/status/responseCode.
- **S7. Verify `.env.local` is gitignored** (add if missing). No secrets are hardcoded in `src` — already confirmed.

## Phase 2 — Guide conformance (Refund stays out of scope)

1. **PKT fix** — `txn.ts` formats via `Intl` Asia/Karachi; expiry = +1 day; `pp_TxnRefNo` = `hij` + PKT timestamp.
2. **Status Inquiry cleanup** — remove the invented `ENDPOINTS.statusInquiry` constant; keep local-DB status route documented as internal; stub comment for the pending official spec.
3. **IPN mapping** — any non-`121` non-empty code → `failed` (guide: `199, 999, others` = failed).
4. **Compliance tests** — `tsx` devDep + `test:jazzcash` script; known-answer test vs the guide's worked HMAC example (salt `3vv9wu3a18`), exact 21-key payload/empty-string/constant checks, amount ×100/÷100, expiry +1 day, PKT offset, billReference sanitization, IPN ack shape.
5. **`docs/jazzcash-compliance.md`** — guide rule → code → test map.
6. Wire `fromJazzCashAmount` into the payment response (`amountPKR`).
