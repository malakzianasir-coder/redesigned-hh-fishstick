REST API for the JazzCash Payment Gateway.

All REST endpoints accept and return application/json. Request and response fields are prefixed with pp_ (core gateway fields) or ppmpf_ (merchant free-form pass-through fields). Every request is signed with an HMAC-SHA256 integrity signature (pp_SecureHash); every response carries a pp_ResponseCode and pp_ResponseMessage whose values are listed in the Response Codes reference below.

Authentication & Secure Hash
Requests are authenticated with your merchant credentials (pp_MerchantID / pp_Password) together with an integrity signature (pp_SecureHash) derived from the request payload and your Integrity Salt. The gateway recomputes the signature and rejects any request whose value does not match.

Algorithm: HMAC-SHA256  |  Key: your Integrity Salt  |  Message encoding: ISO-8859-1 (Latin-1)  |  Output: uppercase hexadecimal

Steps
Select the request parameters whose name begins with pp (case-sensitive), excluding pp_SecureHash itself, and whose value is neither null nor blank. At least one parameter must qualify.
Sort the selected parameter names in ordinal (byte-wise) order.
Concatenate the selected values in that order, joined by &, and prefix the result with your Integrity Salt: {IntegritySalt}&{value1}&{value2}&...&{valueN}.
Sign that string with HMAC-SHA256 using the Integrity Salt as the key, and render the digest as uppercase hexadecimal.
Send the result as pp_SecureHash on the request.
Worked example
Integrity Salt: abcd1234efgh5678ijkl9012mnop3456

Selected parameters (sorted): pp_Amount, pp_BillReference, pp_MerchantID, pp_TxnCurrency, pp_TxnDateTime, pp_TxnRefNo

String to sign:

abcd1234efgh5678ijkl9012mnop3456&100&B20251020210000&MC000000&PKR&20251020210000&T20251020210000
Resulting pp_SecureHash (HMAC-SHA256, uppercase hex):

7F5E94F96F2EDFBA53A75B0D9E0241AC93BE2FE24134E0D11F73C4A0234A373C
Response Codes
Every response returns a pp_ResponseCode indicating the outcome, alongside a human-readable pp_ResponseMessage. 000 indicates the transaction was processed successfully; every other code describes the specific outcome — a decline reason, a pending/interim state, or an error — as listed below.

Payment Portal
Payment via Payment Portal (Page Redirection)
This endpoint handles the redirection process for payment transactions through Payment Portal integration. It creates a transaction and redirects the user to appropriate payment or error page based on the response.
